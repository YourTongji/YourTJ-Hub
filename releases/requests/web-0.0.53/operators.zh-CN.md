# Web 0.0.53 运维说明

## 发布身份

- 固定应用源码为 `3b5288572742bef651da5a7f05afe305349a8516`，上一成功生产基线为 `v0.0.52`（`dc41a82d1edadfb4339b81e25eedadc4d0b38b23`）。Web 预发布运行 `41446524253` 已通过完整验证与部署，负责人已确认实际 QA 和旧客户端兼容性。
- 本请求仅发布 Web。可信 main 控制器包含独立修复 #1547，用于查找已审核的晋级 PR；该修复不替换应用候选。正式发布仍须审核本请求最终 head。
- 由 Web publisher 构建并归档二进制，再用同一 Linux 二进制生成镜像。生产按镜像 digest 部署，备份数据库、等待健康检查并核对运行二进制；不得用 main 最新提交替换固定源码。

## 迁移与数据保留

- 本版本增加 XP 账本、规则和贴纸市场相关 schema。数据迁移到 v37：回填摘要、初始化 XP 规则，并为历史私信媒体和个人封面补登附件引用。确认生产数据库备份可恢复，观察启动迁移状态及耗时；大表新增索引可能阻塞写入，按部署文档安排低流量窗口。
- 搜索索引迁移使用独立水位。Meilisearch 暂不可用时，索引步骤延后，数据库迁移继续；恢复后按部署文档运行 `rebuild-search-index` 并核对搜索结果，不手工跳过迁移水位。
- 未引用上传及其变体在 7 天后回收。确认 v37 的私信和封面引用回填完成，再检查清理任务；不要手工删除存储对象或墓碑来修复引用失败。
- 普通图片读取改为每次校验权限并返回 `no-store`；受限预览与拒绝响应为 `private, no-store`。反向代理应保留这些响应头。旧缓存副本无法追溯撤销，绕过应用的公开对象存储地址仍需独立访问控制；市场贴纸资源继续使用其公开缓存策略。

## 配置与运行边界

- 保留实例声明中的推荐、排序和观测设置，按模板渲染配置并保留生产凭据。通行密钥仍默认关闭，不把域名关联字段已配置视为已启用或设备验收通过。
- 会话 Cookie 的 `cookieSecure=auto` 按 `server.url` 判断；生产应保持 HTTPS，不用 `off` 规避登录问题。通知回调会拒绝本机、元数据等受限目标，检查已有回调是否需要调整。
- XP 账本和单日结算 CLI 已实现，自动定时结算与业务事件接入尚未连接。单日结算默认预演，实际写入需要明确日期、启用边界和 `--apply`；本次部署不自动补发历史 XP。已批准的每日 65 XP 上限尚未写入当前规则，不能宣称已生效。
- Linux 产物使用 `CGO_ENABLED=0` 和 `-tags nodynamic`，保持 Alpine 可运行。宿主机、OpenResty 等独立维护按各自 runbook 执行；本次应用发布不代表这些维护已经完成。

## 上线核验与恢复

- 发布后核对首页、健康端点、OIDC discovery、登录与退出、写作及激活恢复、上传和旧图片权限、贴纸、通知与私信、搜索和排课。检查迁移、清理及邮件任务的失败状态，并复查旧客户端兼容性。
- 任一必要发布步骤失败仍按失败处理，使用原候选和原始产物走 Recover。镜像或配置回滚不恢复数据库；回退前确认旧版本与新 schema、附件状态兼容，不自动覆盖生产数据，迁移不兼容时优先向前修复。
- 证据文件保留了有界 diff 和 PR 元数据覆盖不足的提示；审核者应结合完整源码检查，不能将摘录视为全部变更。移动端需在后续周期完成 dev QA、生产配置演练与设备 QA，再发布 Android、TestFlight 和提交 App Store。

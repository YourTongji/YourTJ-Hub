## Catalog and course identity

`Current`：Web 与 Flutter 提供课程目录、详情、课评和收藏。课程卡以课程代码与身份教师组合唯一定位，
评价归属 `course_id`，教学班评价可用 `offeringId` 聚焦。院系、学期、校区和教师支持多选，同字段内取并集。
Flutter 目录行与筛选行共用一套 chip 规范：可见高度 = `type.meta` + 上下 4dp、圆角 `--gf-radius-selector`（8），
目录行组内 gap 6、组间距 12（≥2×），首个学期、`+n` 计数与下拉箭头合并在同一个 disclosure chip（学期与单学期卡片
同色，展开后换成收起文案与向上箭头并把其余学期排进内层 6dp wrap，换行以组为单位）；chip 行统一按 44dp 命中高度排，
有无展开 chip 的卡片等高，卡片顶、标题→教师、教师→chip、底四段可见间距均匀。筛选 chip 视觉高 32dp、命中区 ≥44dp，
带已选计数徽标与下拉箭头（只看有评价为勾选 toggle），横向滚动两端 12dp 渐隐提示更多内容；有搜索或筛选时行首出现同规格
的 × chip（重置搜索和筛选），不再另起一行把列表下推。
目录与详情课评使用滚动分页；失败可重试，刷新不丢弃已有内容。相关教师展示课程卡的身份教师，缺少时给出本地化占位。

`Current`：配置 Meilisearch 的实例使用课程索引检索关键词，包括教学班号和教师拼音／首字母；
精确筛选、可见性、评价顺序与总数仍由数据库决定。搜索故障明确报错，不能伪装空结果；
未配置搜索的本地环境保留 SQL 匹配。筛选选项最多延迟五分钟更新，关键词遵循搜索引擎分词。
课评正文不进入课程搜索索引。见[课程检索契约](../architecture/contracts-and-data.md#course-catalog-keyword-retrieval)。

`Current`：课程评价聚合范围可为教师、教学团队或课程；团队按共同 `team_key` 聚合评分与教师。
课程沿革支持等价、改名等关系，候选需管理员审核。合并迁移教学班及其评价、教师关联，保留可撤销证据，
旧卡隐藏；冲突别名跳过并记录。详情显示原名与有方向的沿革，教学班身份和隐藏状态不能被导入意外重置。

## Reviews and moderation

`Current`：用户可发表、修改和删除评价，并进行有帮助反馈、举报及课程收藏。匿名作者不进入公开 DTO；
课程管理员可隐藏／恢复并处理举报，只有 Admin 填写理由后可揭示身份，操作必须审计。
已删除评价经过 30 天隔离后清除内容和作者关联，释放唯一槽位并保留审计记录；清理可由定时任务或 CLI 执行。

`Current`：Flutter 详情页用统一 Markdown renderer 阅读评价，卡片显示头像：member 用服务端 `avatarUrl`，
服务端相对路径先解析为绝对地址；匿名与历史评价（以及加载失败的网络头像）用与 Web 同 seed 的生成头像，
同一条评价在两端是同一张脸。卡片元信息收敛为一行：作者行下方是「学期 · 班次 · 教师 · 短日期」
（七天以内用相对时间，更早用 `M月D日`，跨年才带年份；班号、校区、院系已在课程头部与开课记录里，不在卡片重复），
常规字号下可单行放下，过长时整行换行而不截断。富 Markdown editor 提供六种 Web 同步模板，
块级字号与阅读态 compact 档位一致，模板在现有 controller 上原地插入（保留焦点与撤销栈，非空正文仍需确认替换；「快速评价」的待填 `-`
逐行落成空的无序列表项，不会吞掉上方的「优点/缺点」；光标落在首行标题或「总体评价：」标签之后，续写不继承粗体），
图片可从相册选择后复用 `/file/img-upload` 直传链路并插入正文。功能区固定单行：有用／无用计数（等宽数字槽位）
+ 分享图片，可见 pill 高 32dp、字号 13、图标 16，命中区仍不小于 44px，窄屏或大字号下整行横向滚动而不折行；
编辑／删除收进卡片右上溢出菜单，
举报（仅登录用户可见）在同一菜单中，须选择理由并可附 300 字以内说明。写评／编辑 sheet 采用编辑器优先布局：
键盘弹出时面板高度收敛到键盘之上，工具栏与底部动作常驻，正文在自身内部滚动；班次选择 chip 与五颗 48dp
星级同排（chip 贴左、星级贴右，放不下时自动折行），发布身份独占下一整行
（非匿名显示当前用户头像+昵称与「以 xxx 发布」，匿名显示完整主文案+「对公众隐藏身份」说明），320dp +
200% 字号不截断。评分区左侧是均分进度环（104dp、8dp 描边、圆角端点、起点正上方，与 Web 同一几何的
`warning → primary` 线性渐变（右下→左上），弧起点没有扫掠渐变的黄/蓝接缝，弧尾带 primary 实心 + 卡片底色描边的光点），右侧 5→1 分布条
（6dp 圆角条、warning 同色相亮度阶梯 5★ 0.95 → 1★ 0.24、等宽数字右对齐、计数列随字号缩放）；均分缺失时只显示安静占位。匿名及历史评价分享继续使用公开
DTO 的作者标签，分享卡是一张浮在更深底色上的白卡（20 圆角、发丝线描边、两层柔和投影）：课程名（22）+「教师 · 院系 ·
课号」，一行读完的数据条（本条评分与星级｜课程评分｜课评数，发丝竖线分隔），正文与阅读态同源使用服务端
`contentHtml`（16/1.7、标题级差 19/18/17/16），发丝线之后是署名（头像、作者、「开课信息 · 日期」）。所有文字允许
换行、不做省略号截断；手帐感点缀（主题标志色斜纹纸胶带、星级同色四角闪光、卡后探出的网点与细圆环）只落在外边距
与卡片边缘、不压文字，不使用渐变、发光或彩条；未点亮的星为描边星，五格刻度始终可见。主题色卡为卡片底色｜主题标志色的
对角拼色圆（纸白取石板灰以区别晴蓝），选中带主色外圈；次要文字与数据条在五个主题下经过 AA 对比度校验；
固定 375 逻辑宽、3× 高清捕获且预览与导出为同一张卡。底部「收藏/写课评」为独立底栏，列表视口不与其重叠。

`Current`：有用与无用使用两个独立 API；切换时服务端在单个事务中删除相反状态并写入目标状态，且按评价行串行化
并发变更，避免同一用户对同一评价同时处于两种状态。Flutter 在同一帧内乐观更新本地两侧状态与计数，并先清掉已选中
的相反状态（幂等）再写目标状态，旧服务端也能得到同样的互斥结果；失败时给出本地化提示：若清相反状态已成功而写目标失败，
本地回滚为两侧均未选（与服务端一致），否则恢复原状态与计数；不重读整表、不触发列表 loading。

`Current`：AI 课程总结使用管理端可热更新的 provider 配置，密钥加密保存且不回显；
未配置管理端模型时可回退运行配置。至少一条可见有正文评价才可生成，总结与评价不足状态均持久化，
评价变化使其失效。只读预检不生成内容、不消耗生成配额；刷新可强制重评，数据不足及失败不占用单课生成名额。
界面明确区分已有总结、评价不足、未生成、服务关闭与失败状态，不把模型输出当作官方课程信息。Flutter 头部行是
「sparkles 方标 · AI 总结 · 结论 pill」，结论折叠时也可见；右侧刷新与展开两个图标按钮并排贴右（44dp 高命中区，
刷新中换成同尺寸 spinner 不跳动）。展开后依次是一句结论导语、单行横滑的 #关键词（边缘渐隐，不换行不截断）、
优缺点合为单列（+/− 圆点区分、组间多留 4dp，与 Web 一样各取前 4 条），代表性评价为等宽等高的中性小卡
（base200、box 圆角、情感小圆点），多条时横滑并露出下一张。

## Scheduler

`Current`：Web 与 Flutter 的排课器按学期、年级、专业选课，支持必修、选修、搜索与时间段入口；
可筛选周次、查看教学班评价、收藏课程并导出课表。冲突课程仍可加入，选择教学班前及课表中给出冲突提示。
同一时间的单双周课程在周次不重叠时不算冲突；同班同天多段安排合并展示，自定义占位参与冲突计算。

`Current`：用户可新增、切换、删除、清空、重命名和复制方案；Web 支持同一选课上下文内的方案对比。
各方案独立保存课程和自定义占位，“同步最新”按课程代码保留已选状态。Web 提供 CSV／XLS／PNG 导出，
Flutter 提供 CSV／PNG；有冲突时导出前提示，PNG 使用独立海报。官方个人课表与排课器方案严格分开，
官方课表读取或 Widget 更新不覆盖排课方案。

`Current`：学期 `calendarId >= 120` 使用 11 节作息，历史学期使用内置 12 节表。
现行作息可由管理员热配置并经 SSR／刷新同步，旧配置按编号版本归一；新配置不影响历史学期。
当前教学周依赖服务端学期起始日，未配置时禁用定位。排课 API 的字段和操作清单以
[生成的契约覆盖矩阵](../../packages/api-contract/coverage-matrix.md)为准，不在产品文档手写端点数量。

## Plan synchronization

`Current`：Web／App 按方案使用整数版本与条件写，云端最多十套方案、每套 1 MB；不同方案互不争抢版本。
同一方案按课程与自定义事件字段三方合并，只对真实冲突项请求选择。远端已删除而本地仍有修改时，
用户确认保留的内容进入独立恢复草稿，恢复创建新 ID，不能复活被删方案。

当前方案、专业与周次仅属于设备偏好。修改后防抖三秒，进页、间隔至少三十秒的重新聚焦及联网恢复触发同步；
只有未同步修改退避重试，没有干净状态心跳。各账号本地数据及同步基准隔离，访客方案上传需确认；
注销擦除云端方案并阻止迟到请求重建。移动端交互详见[移动端体验](mobile-experience.md)。

## Import and administration

`Current`：一系统本科与研究生受众分别保存凭据、抓取状态和课程快照，物化及补跑使用所选受众；
公开排课查询默认本科。管理端提供凭据探测、学期同步、独立目录物化与定时同步，失败通知有权限的活跃管理员。
离线导入验证 manifest、校验和与授权引用，支持 dry-run、隔离失败记录及幂等重试。

当前公开课程编号使用 `newCourseCode`／`newCode`；源编号只作沿革证据和历史方案兼容。
教学班权威来源为一系统物化；教师变更保留教学班 ID 与评价，旧数据包兼容复用已有记录。
活动或抓取不完整的学期不能物化。凭据来源、定时任务、失败通知、重建和补跑命令统一见
[课程同步运维](../operations/deployment.md)，搜索索引修复见[契约与数据](../architecture/contracts-and-data.md#managed-search-reconciliation)。

## Boundaries and evidence

Web、API 与 Flutter 课程／排课页面为 `Current`；移动端商店发布、原生推送及学校真机认证的验证缺口
见[移动端体验](mobile-experience.md)和[移动发布指南](../operations/mobile-releases.md)，不将整个课程 UI 标为未实现。

接口结构以 [OpenAPI](../../packages/api-contract/openapi.yaml)、生成类型与路由契约测试为准；
课程与排课规则分别由 `courseservice`、`pkservice` 和各端页面测试维护。
[测试指南](../development/testing.md)说明各检查的覆盖范围，本地子集通过不代表生产数据或全平台验收通过。

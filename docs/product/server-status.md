## 页面与数据范围

**Current**：`apps/status` 提供无需登录的独立状态页面，目标域名 `status.yourtj.de`。
论坛侧栏只保留「运行状态」外链。
页面不依赖论坛 API、Cookie、字体服务器或论坛静态资产。字体、色彩、面板和间距沿用
YourTJ 视觉语言，支持明暗主题、手机布局与中文／英文／日文／德文。

**Partial**：Cloudflare 静态资源、只读 Worker API、私有 R2 与 GitHub Actions 采集已实现，
读取器通过隔离预览验证；生产域名仍指向 Netlify，正式采集与设备统计尚待配置和验收。
下述十五分钟采集及新鲜度规则描述 Cloudflare 实现，不能视作正式站已经启用。

- **服务可用性**：独立 Uptime Kuma 已发布状态页的监控项、最新检查／响应时间、
  来源计算的近 24 小时可用率与最近最多 100 次真实检测。可用率基于已采集数据，可能
  不足 24 小时；检测条不是每日可用率，不补绿色。悬停及键盘聚焦的详情原位过渡，
  连续扫过条间空隙不闪烁、不改变面板高度；支持 Escape 和减少动态效果设置。
- **服务器**：仅展示配置的一个 Komari 节点，包括当前 CPU、内存、磁盘、网络速率、
  主机运行时长和 CPU／内存曲线。资源历史独立切换 `1h/6h/24h/7d`，默认 `1h`，
  当前资源卡始终使用最新采样。历史缺失不补零；最多 120 点并保留整个范围，明显
  采样间断会断开曲线；跨日范围的时间轴同时显示日期和时间。历史内存容量缺失时，
  使用当前主机容量折算，并在页面披露。
- **访问统计**：Umami 公开共享页的独立访客、浏览量、访问次数、跳出率、平均访问
  时长和采集时最近五分钟的独立访客，支持滚动 `24h/7d/30d`。在线人数是采集快照，
  不宣称浏览器访问时的实时人数。趋势按 UTC 小时／天分桶，显示使用浏览器时区；
  分桶独立访客不能相加当作全范围独立访客。跳出率按跳出访问／访问次数计算，
  平均时长按访问总秒数／访问次数计算；无访问时为缺失值。
- **访客设备分布**：Umami Breakdown 联合统计的设备 → 操作系统 → 客户端桑基图，
  独立切换滚动 `24h/7d/30d`，默认 `7d`。线宽表示该范围内访客人数，不代表跨设备
  迁移或访问路径。仅显示预定义设备类型、系统家族和浏览器家族；少量系统／浏览器
  类型合并为「其他」，未识别类型单独保留。悬停、键盘聚焦或轻触可查看人数和占
  已展示访客的比例；连续切换详情保留面板高度，支持 Escape 和减少动态效果。
  手机分两步显示设备／系统、系统／客户端，避免压缩文字。
  联合报表与同一时间窗口的访客总数核对；达到上游 500 行限制或数量不全时明确显示
  覆盖人数，不填造剩余流量。数量不合法或重复计数导致超过总人数时采集失败。

容量使用 MiB/GiB，网速使用字节每秒。缺失值显示 `—`，真实零值显示 `0`。
UI 脚本必须启用才能读取指标；无脚本入口提供独立 Uptime 页面链接。

## 状态与新鲜度

页首优先使用独立 Uptime 检测，保留可访问、异常、部分异常、维护、待确认与未知。
来源过期／不可用、没有最新检测、检测超过二十分钟时都不能显示正常。未配置 Uptime
时才退回探针上报信号；高 CPU 或主机运行时长不代表网站可用率。

GitHub 定时运行可能延迟；页面明确展示采集频率、获取和采样时间，独立监控仍承担告警。

**Partial**：当前资源、Uptime、资源历史与访问统计由 GitHub Actions 每十五分钟采集；
设备分布每小时采集。浏览器每 60 秒读取同源 `/api/status`，隐藏页面时暂停；手动刷新
与范围切换立即读取已有快照。范围切换取消旧请求并忽略乱序
响应，切换资源曲线时不把旧范围曲线标成新范围。公开 API 只读快照，访客请求与取消
不会触发上游采集；采集端预组装视图，每次 API 最多读取两个 R2 对象，动态响应不缓存。

当前资源、可用性、历史与流量获取时间超过二十分钟为过期；
设备分布超过七十分钟为过期。
主机最新采样也须在二十分钟内；所有获取／采样／检测时间最多容忍一分钟未来偏差，
无效时间不作为健康信号。资源历史有独立获取时间和过期提示，不能随当前资源刷新
冒充新历史。浏览器即使反复读到缓存也会按原始时间重新判断状态。

上游采集失败保留上次成功数据及其时间戳，立即标为过期。当前数据最多保留一小时，
历史与流量最多一小时，设备分布最多三小时；超过各自保留期返回不可用及空数据。
实时资源失效不移除仍在保留期内的历史曲线；页面隐藏实时读数，历史单独显示过期提示。
API 的 `server.state/fetchedAt` 仅描述实时来源；历史仍可在 `server.data` 中返回，此时
`current/cpuCores` 为 `null`、节点名称和区域为空，历史依自身获取时间判断新鲜度。
读取 R2 失败返回 503，页面取消正常状态，保留的指标和图表仍按原始时间过期，
不会无限延长展示。来源配置变更切换缓存身份，停用来源不会继续读取其旧快照。

## 隐私与故障边界

基础统计采集公开 Umami 共享统计、公开 Komari 指定节点和已发布 Uptime 监控项。
设备分布可选配置有目标网站读取权限的 Umami 账号，在后台查询联合报表并输出固定
类别白名单及人数；不开放原始报表或扩大共享链接权限。账号凭据仅在服务端环境变量
中配置，登录 token 仅在一次采集中复用，不持久化、不返回浏览器。未配置账号不影响
基础统计。设备分布有独立快照、获取时间和失败状态，使用前述设备专用的过期及保留规则。
浏览器无法指定上游 URL、节点、网站或任意报表维度。服务器 IP、账单、备注、访客会话、
访问路径、检测目标 URL、上游错误文本和自定义 CSS 都不在公开响应中。

状态站的页面、采集和快照读取都独立于论坛；Uptime Kuma 已独立部署。监控站或 Cloudflare
自身发生故障时，页面依数据年龄显示未知／过期，不能把缺少数据判为网站正常。

**Partial**：独立应用、API 契约、测试和部署配置已具备；Cloudflare Worker、正式 DNS 与云端
定时采集仍需要运营配置并验收。Flutter 原生页面没有实现。

**Planned**：事故公告管理、长期每日可用率历史与通知订阅。

权限、隐私、保留与失败边界的批准记录：[STATUS-ANALYTICS-926-927](https://github.com/YourTongji/YourTJ-Hub/pull/926#issuecomment-5874262017)。

## 配置与契约

按[Cloudflare 部署手册](../operations/status-cloudflare.md)设置项目、环境变量与域名。
独立 API 以 [`apps/status/api/openapi.yaml`](../../apps/status/api/openapi.yaml) 为准，
生成 TypeScript 与验证在同一应用维护。论坛 Gin API 和移动客户端不包含状态数据镜像。

## 原生客户端识别

`Current`：客户端列仅将明确携带 `browser: yourtj-app` 的上报显示为 **YourTJ App**，即使占比很小也保留单独节点。正式 Android/iOS App 连接正式站时自动统计公开页面，无需设置开关；范围见[移动端隐私说明](mobile-experience.md#profile-and-privacy)。普通 WebView 仍显示“内嵌浏览器”，不猜测来源。历史数据无法补回 App 身份。Umami 访客不是账号人数，Web 与 App 不做身份合并。接口保留 `browser` 字段名，枚举包含 `yourtj-app`。

`Partial`：统计覆盖取决于客户端版本和成功上报，离线或请求失败的访问可能缺失。自动统计版本扩大覆盖面后，App 占比与访问量不能直接与旧版自愿启用的样本比较；实际线上分布仍需随发布核验。

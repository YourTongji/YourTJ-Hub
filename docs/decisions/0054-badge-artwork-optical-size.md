# 徽章图形光学尺寸归一化与角标图标区

## Status
Accepted
Class: feature

## Context and Problem Statement

15 个系统徽章 SVG 的光学尺寸互不一致：`first-*` 一批顶满 24×24 画布，而 `liked-10`、
`contributor`、`sponsor` 四周留白明显，最大与最小相差约 1.5 倍。放进头像右下角的圆形角标后，
最大的几个图标（小有名气、初次评论、被看见了等）贴到甚至压过圆环——个人主页 112px 头像最明显，
实测达到角标可用半径的 106%～111%。

角标自身也有尺寸漂移问题：图标内边距固定 2px、角标高度取头像的 30% 且有 14px 下限，导致图标区
占角标的比例随头像尺寸变化（个人主页 87.7%，被下限钳制的小头像 71.4%）。因此「只缩角标」会连
观感正常的基准徽章一起缩小，「只缩图形」又会让小头像上的图标缩过头（h-6 场景从 86% 降到 59%）。

## Decision Drivers

- 所有系统徽章统一到一个光学尺寸，对齐本就没有被反馈过的基准徽章（受到认可 / 贡献者 / 赞助者）。
- 屏幕上的描边粗细与改前一致：缩小图形不得让线条变细、变淡。
- 不变量可机器守卫，而不是靠目测。
- 已上线用户必须真的看到新图形：`/static/*` 的长公共缓存不能把旧图形留在浏览器里。
- 不改接口结构与 i18n；Web 与移动端继续共用同一批 SVG 资产。

## Considered Options

- 图形归一化到墨迹半径 10/24 并补偿描边，角标图标区改为固定占 88%（已采用）。
- 只归一化图形，角标容器不动。
- 归一化目标取角标可用半径的 80%（而非基准徽章的 73%）。
- 角标改用百分比内边距（如 `p-[6%]`）替代百分比图标尺寸。

## Decision Outcome

选择「图形归一化 + 角标图标区固定 88%」。12 个偏大的 SVG 外包一层以画布中心为基准的均匀缩放
`translate(12 12) scale(s) translate(-12 -12)`，缩放系数 0.6329（小有名气）～0.9119（机器人），
描边按 `stroke-width = 2/s` 补偿，使渲染后的描边半宽恒为 1 单位；`liked-10`、`contributor`、
`sponsor` 保持原样。角标去掉固定 `p-[2px]`，图标改为 `h-[88%] w-[88%]`，各头像尺寸下图标区占
角标的比例一致，个人主页观感不变、小头像不再额外缩水。

改后实测：15 个图标在个人主页角标上占可用半径 73.0%～73.3%（与「受到认可」改前一致），同一
图标在个人主页 / 用户卡片 / 楼层 / 回复行四种尺寸下占比相差不超过 2 个百分点。守卫测试
`resource/test/badge-icon-optical-size.browser.mjs` 断言「不碰圆环（≤80% 可用半径）+ 视觉等大
（≤5 个百分点）+ 各尺寸一致」，并在文件层校验「均匀居中缩放 + 1/scale 描边补偿」。

## Pros and Cons of the Options

- **只归一化图形**：改动最小，但小头像因固定内边距会被额外缩小，h-6 场景掉到 59%，观感退化，
  因此两半改动必须同时落地。
- **目标取 80%**：在 h-6 上更接近改前观感，但实测量到 79.9%，正好贴着守卫阈值，余量不足；且
  基准徽章原本就在 73%，选 73% 才能与「观感正常」的参照对齐。若不满意，可改缩放系数并同步放宽阈值。
- **百分比内边距**：CSS 百分比 padding 相对父容器宽度（这里是头像而非角标）解析，个人主页上会
  变成约 6.5px；且移动端容器独立于 Web，改不到。百分比图标尺寸没有这两个问题。
- **采用的方案**：代价是描边宽度保持 2 单位而图形缩小，线条相对图形变粗，增幅为 1/s
  （机器人约 +10%，小有名气约 +58%），内部空隙按比例变窄，偏离了这些图标原本的设计样貌；
  好处是 15 个图标的线宽与图形之比一致，与未缩放的基准徽章相同。若不接受，可改为描边随图形
  等比缩放（线条变细）或单独重绘图标。移动端共用同一批 SVG，角标占圆环内沿的 83%。移动端特有的徽章牌
  （`GfBadgeMedallion`）原来的中心盒只有牌面的 60%，归一化后图形只剩牌面直径的 37%～42%，
  显得空；因此中心盒放大到 70%（`GfBadgeMedallion.artworkSize`），徽章图形改用
  `UserBadgeArtwork.medallion` 填满中心盒，四种牌面尺寸（80/56/40/34）下墨迹直径统一为牌面的
  48%～54%（原先 37%～63% 参差不齐）。图形自带边距，放大中心盒不会碰到牌面边缘。
- **自定义徽章**：只有 `/static/badges/` 下的内置图形自带统一边距。自定义徽章的图形（线上在用的
  是外链品牌 logo）往往铺满画布，跟着放大会在小头像角标上压到圆环、在徽章牌里比内置徽章大一圈。
  因此按图标地址区分：Web 角标对自定义图形保留 2px 内边距并填满（与改前一致）；移动端
  `UserBadgeArtwork.medallion` 对自定义图形仍按牌面 60% 取尺寸。
- **缓存失效**：`/static/*` 在 production 带约 210 天公共缓存且不做重验证，图形改了而 URL
  不变，老用户会一直看到旧图形。因此 `badgeservice` 输出徽章时给 `/static/badges/` 下的 URL
  附加 `?v=<badgeAssetVersion>`（覆盖记录里回存的旧版本号会被替换），Web、移动端与新发出的
  徽章通知都走这条路径；以后改动这批 SVG 时递增 `badgeAssetVersion`。

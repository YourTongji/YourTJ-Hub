# 学校验证后由用户完成论坛注册

## Status
Accepted
Class: architecture

## Context and Problem Statement

同济认证已经验证校内身份，无需再发送邮件才能设置论坛密码。首次注册仍需要用户选择公开用户名和登录密码；学校回调直接生成随机用户名、无密码账号不能满足这一需求。

## Decision Drivers

- 学校身份与既有账号、邮箱占用和每日额度仍有明确边界。
- 注册提交前不创建账号，不产生无人认领的初始化积分或论坛会话。
- Web 和 App OIDC 使用同一注册流程，保留原安全返回地址。
- 密码与绑定在同一事务提交，凭据不可重放或转成修改已有账号密码的能力。

## Considered Options

- 学校认证后暂存注册证明，用户填写用户名和密码后原子注册。
- 回调立即创建随机用户名、无密码账号，再通过邮箱找回设置密码。
- 回调创建账号后给予一次直接修改密码的权限。

## Decision Outcome

选择暂存注册证明，替代 [0032](0032-tongji-login-and-registration.md) 的即时随机用户名、无密码注册方式。其身份权威、唯一绑定、邮件占用、永久 HMAC 保留、每日限额和环境隔离规则继续适用。

回调对已有绑定仍直接登录；从未绑定身份进入 `/register/tongji`。加密学校凭据与原站内返回地址在进程内暂存，受原授权十分钟期限和容量上限约束；浏览器只持有 API 路径限定的 HttpOnly、SameSite=Strict 注册 cookie。独立 CSRF token 从不缓存的同源状态接口取得。重启和过期要求重新认证。

完成接口复用注册用户名、保留名和密码规则，重新核验注册政策，在一个事务内创建已激活普通用户、密码 hash、初始化数据和加密学校绑定。失败不保留账号或身份占位，可以在期限内改正输入后重试。成功消费证明、签发普通论坛会话并恢复原目标地址，包括 App OIDC 续接。不存在重设已有账号密码、根据邮箱自动合并或提升首用户权限的分支。

## Pros and Cons of the Options

- 暂存证明：用户自主确定凭据，省去重复邮箱验证；需要短期注册状态和过期重试界面。
- 回调即时创建后邮箱找回：复用现有恢复，但重复身份验证且留下随机公开名称，不满足注册体验。
- 已创建账号的一次改密能力：流程较短，但扩大已有会话的敏感操作权限并留下未完成账号，边界更复杂。

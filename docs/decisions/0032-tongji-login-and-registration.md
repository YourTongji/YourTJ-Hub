# 同济统一认证登录与自动激活注册

## Status
Accepted
Class: architecture

## Context and Problem Statement

用户需要在 Web 和 Flutter 的登录、注册入口通过同济统一认证进入论坛。学校已验证身份可创建账号并按学号设置校内邮箱，免去重复填写邮箱和邮件激活；现有校园绑定仍须双向唯一。该要求改变了 [0031](0031-campus-official-identity.md) 中学校身份不参与论坛登录、学校回调不创建账号的决定。

## Decision Drivers

- 保留论坛 numeric user ID、可撤销的论坛会话和原有登录方式。
- 复用学校身份签名校验、回调地址、双向唯一绑定和服务端凭据加密。
- 保护已有账号，禁止依据推导邮箱自动合并账号或覆盖账号字段。
- 注册与身份绑定原子提交，不创建没有登录身份的孤立账号。
- 学号和姓名不成为默认公开用户名或昵称。

## Considered Options

- 用独立登录用途的学校授权，直接复用校园身份索引并原子注册。
- 把学校身份复制到通用 OAuth 表并与校园绑定分别维护。
- 保留纯校园连接，只在密码注册后进入校园页绑定。

## Decision Outcome

选择独立登录用途、复用校园绑定索引，替代 [0031](0031-campus-official-identity.md) 的登录限制；其服务端持有学校凭据、私密数据及环境隔离原则继续适用。

`GET /api/auth/tongji` 生成十分钟、一次性的登录 state、nonce、PKCE verifier，使用独立 HttpOnly 浏览器 cookie 绑定此次流程。学校继续回调 `/api/campus/tongji/callback`；登录用途要求浏览器证明，普通绑定用途仍要求原论坛会话和后续确认，二者不能互换。安全站内返回地址在开始时保存在服务端，回调参数不得改变它。Flutter 通过内建 OIDC 的 `login_hint=tongji` 进入相同流程，保留移动端 PKCE、nonce 与浏览器绑定。

学校签名和身份校验通过后，已有校园身份绑定登录对应的可用人类账号，刷新该绑定的加密凭据；不重置邮箱、激活状态、密码或角色。从未绑定过的身份，只有有效数字学号可以推导 `学号@tongji.edu.cn`，按注册开关、域名白名单和每日限额创建已激活的普通人类账号。随机公开用户名和昵称不包含学校身份；不设置本地密码、不赋予首用户管理员权限，邮箱找回流程可用于设置密码。

账号、初始统计与积分、加密校园绑定在同一事务内提交。当前邮箱、有效待确认邮箱和已注销账号保留的邮箱占用均不自动合并。用户需要先恢复或登录已有账号，再绑定学校身份。校园解绑释放学校登录关系，不撤销之前授予的正常激活状态、不改变已绑定邮箱；邮箱仍受普通账号生命周期管理。独立身份保留表仅保存 HMAC 指纹，不关联用户 ID，解绑、换绑和注销后长期保留；同一身份不能再次自动注册或领取初始化积分，但可以显式绑定已有账号。迁移从当前绑定幂等回填，失败的注册或绑定不留下保留记录。身份密钥须长期稳定，生产和 dev 的绑定及保留记录均不互相复制。密码注册与学校注册在数据库事务内共享每日名额锁，回滚释放名额，注销不恢复当天名额。

## Pros and Cons of the Options

- 复用校园身份：一次认证即可进入论坛和校园，登录与解绑始终使用同一权威关系；代价是校园身份更换也会改变学校登录身份，需明确用户提示与账号恢复规则。
- 复制通用 OAuth 关系：能复用更多 goth 处理，但会出现两套解绑与换绑事实，增加身份残留或错误登录风险。
- 仅注册后绑定：保持原语义，但无法满足免填写邮箱、免邮件激活的一步注册需求。

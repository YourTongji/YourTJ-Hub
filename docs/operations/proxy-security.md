# 1Panel OpenResty 安全维护

> Doc type: reference
>
> Status: Active
>
> Owner: Platform maintainers
>
> Last verified: 2026-10-22

本页负责面板管理的 TLS 代理更新。[部署文档](deployment.md#deployment-shape)负责代理拓扑、
可信代理、SSE 与缓存契约。代理由 1Panel 管理，不在论坛 compose 中；更新论坛 Alpine 镜像不会更新它。

## 选择候选

在安全 Issue 中记录风险条件、候选镜像 digest、来源、兼容性和恢复方式，经 PR 评审。
核查实际二进制的 NGINX/OpenResty/OpenSSL 版本、编译模块和发行方回补补丁，
对照 [NGINX 安全公告](https://nginx.org/en/security_advisories.html)与
[OpenResty 发布说明](https://openresty.org/en/download.html)。不能只看镜像 tag，
也不能仅因某模块被编译就断言漏洞可利用。逐项检查实际启用的指令及完整 include 链；
未能检查的配置明确列为缺口，不通过关闭告警处理。

候选须与当前 1Panel 应用定义、配置生成方式、动态模块、证书布局和权限兼容。
不要直接用通用 NGINX 镜像替换 OpenResty，也不要在运行中的旧容器里覆盖二进制。
新版本仍可能缺少后续公告的补丁，须核对具体漏洞及回补证明。
仓库维护的受限候选及尚未修复的 NGINX 边界见[安全镜像说明](../../services/proxy/README.md)。

## 隔离验收

在主机 root 专属目录建立带时间戳的配置、证书及面板应用定义备份，保留权限与旧镜像 digest。
配置与证书不离开受限环境，不上传 GitHub。复制完整配置树用于候选测试，候选不得写入生产目录；
日志、PID、临时文件与证书续期状态使用独立目录，禁止共享生产 Docker socket。

先在隔离网络中执行完整配置语法检查，再测试候选代理；不使用 host network，不抢占公网 80/443。
需要端口映射时仅绑定回环地址，且显式给出测试上游地址；隔离容器内的 `127.0.0.1` 指向容器自身，
不能直接复用指向宿主机回环端口的生产 upstream。
禁止为测试把论坛或数据库端口改为公网监听。测试 upstream 可使用隔离实例，
但必须另外验证切换方案中的真实上游可达性，不能把模拟 upstream 当作生产连通性证据。

候选必须通过：

- 完整 include 与动态模块加载、配置语法、文件权限及证书读取检查。
- 对真实域名发送正确 Host/SNI 的 TLS 握手，验证证书链、过期时间及主站/dev 路由。
- 代理请求保留可信客户端 IP；登录 Cookie、重定向、附件与上传大小限制保持兼容。
- 按[部署缓存验收](deployment.md#静态资产缓存反向代理注意事项)检查响应头，
  SSE 首帧与心跳及时到达，连接不中途缓存；测试不得产生真实业务写入或压力负载。

## 切换与回滚边界

[NGINX HUP/reload](https://nginx.org/en/docs/control.html)重新读取配置并平滑结束旧 worker，
不等于替换容器中的 NGINX/OpenSSL 二进制。更换镜像通常需要重建容器，不能把 reload 成功当作安全升级完成。
官方的 USR2 原地二进制升级也不能未经面板与模块兼容性演练就套用于容器更新。

单代理实例无法保证重建期间完全无中断。执行前必须确认维护窗口，或先验证并行代理及流量切换方案，
包括端口归属、健康探测、长连接排空、TLS 和失败回切。持续 SSE/WebSocket 连接亦需明确恢复行为。
不临时修改防火墙、DNS 或公网监听来绕过该前提；这些变化须有独立风险约定。

通过 1Panel 支持的方式应用已验证候选，避免面板下一次生成配置覆盖手工改动。
切换后核对实际运行二进制、镜像 digest、外部 TLS、主站/dev 健康与上述业务契约。
失败时用备份应用定义和旧镜像恢复端口、挂载、配置与证书，再核对外部访问；
代理回滚不得回退业务数据库。旧镜像含已知风险，只作限时恢复，并继续保留安全 Issue。

隔离测试通过只证明候选在测试条件下工作；生产切换、外部访问与恢复尚未验收时，
不得关闭 Issue 或声称服务已安全升级。
